# Dataset documentation

The repository contains no provenance file for `data/`. The sources below were identified from file
naming and image properties, and **must be confirmed** by whoever added the data before any public
release, including confirming the licences.

## Counts (measured)

| Disease | Folder | Classes (count) | Image format |
|---|---|---|---|
| TB | `data/tb/` | Normal (150), Tuberculosis (150) | 512×512 PNG, mostly greyscale; some RGB (incl. cyan-tinted photos of film) |
| DR | `data/dr/` | No_DR (150), DR (150) | 224×224 PNG, RGB, **Gaussian-filtered** (grey background, no black surround) |
| Oral | `data/oral/` | Normal (150), OSCC (150) | 224×224 JPEG, RGB, filenames `aug_*` (**pre-augmented**) |

The TB split is locked in `data/tb/splits.csv`: train 212, val 44, test 44. That file contained Windows
absolute paths from the original machine. `src/data.resolve_paths` remaps them to `data/tb/<class>/<file>`
without changing the split. DR and oral splits are created deterministically (seed 42, 70/15/15
stratified) on first training run.

## Probable sources

| Disease | Probable origin | Notes |
|---|---|---|
| TB | *Tuberculosis (TB) Chest X-ray Database* (Rahman et al., Kaggle). The naming `Normal-N.png` / `Tuberculosis-N.png` matches | check the dataset licence and citation |
| DR | Kaggle "Diabetic Retinopathy 224×224 Gaussian filtered", derived from **APTOS 2019** (hash-like IDs) | APTOS competition data has usage restrictions. "DR" = any grade 1–4, **not referable DR** |
| Oral | Kaggle oral cancer histopathology (Normal / OSCC) with offline augmentation | `aug_*` names mean augmented copies |

## Known issues

1. **DR preprocessing domain.** The images are already Ben-Graham filtered. A model trained on them may
   not generalise to raw fundus photographs. The packager therefore declares
   `input_domain: "ben_graham_filtered"`, and the app returns `INCONCLUSIVE` for raw-looking photos.
2. **DR label meaning.** "DR vs No_DR" is not "referable vs non-referable". The UI shows the model's own labels.
3. **Oral leakage risk.** Pre-augmented copies of one source image can land in both train and test,
   which would inflate test metrics. Group-aware splitting by source image needs the original IDs, which
   are not available here.
4. **Size.** 150 images per class gives wide confidence intervals. `src/evaluate.py` reports a bootstrap
   AUC CI for this reason.
5. **No demographic or device metadata**, so subgroup performance cannot be assessed.

## Demo samples (`data/samples/`)

Created by `scripts/make_demo_assets.py`, with provenance written to `data/samples/PROVENANCE.json`:

- `sample_chest_xray.png`, `sample_fundus.png`, `sample_histopathology.jpg`: copied from the **test** split
  (positive class) of the bundled data. They are not used for training, and are subject to the original
  dataset licences.
- `invalid_blurry.png`, `unsupported_synthetic.png`: **synthetic** images generated by the script.

## Gatekeeper data

`src/prepare_gatekeeper.py` builds `data/gatekeeper/` from the three disease folders plus a user-supplied
`other` folder of unsupported images (at least 50). No such folder is included, so the gatekeeper cannot be
trained from this repository alone.
